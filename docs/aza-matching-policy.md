# 字の名寄せ方針

住民基本台帳の町字別人口Excel 15年分（平成23年〜令和7年 / 2011〜2025）を1本の推移として
つなぐための方針。

**論点1〜5はすべて決定済みです（2026-07-31）。** 各論点の「選択」欄を参照してください。
未確認のまま残した項目は「未決のまま残すもの」にあります。

ここを間違えても画面はエラーを出しません。字の系列が静かにずれたまま公開されます。
だから機械に決めさせず、人が決めました。

## 決定の要約

| 論点 | 決定 |
|---|---|
| 1 — 分類A・B（471グループ）の名寄せ | **A案＋衝突検知**。正規化ルールをコードに持ち、同一年に複数表記が来たらその年の変換を失敗させる |
| 2 — 分類C・Dの異体字（9件） | **B案**。crosswalk に9行。9件すべて合算。表示名は最新年の表記 |
| 3 — 分類Eの区画再編（5件） | **B案**。つながない。`succeeded_by` / `split_into` で関係だけ記録 |
| 4 — 基準日の混在 | **D案**。推移グラフの横軸を年番号から `date` の実日付に変える |
| 5 — 人口ゼロの見せ方 | 検索では出し一覧では畳む／掲載なしの区間は線を切る／残余字は丁目へリンク |

論点1〜3を適用すると、系列は **1,780 → 約1,300**、15年揃うものが **673 → 約1,130** に
なります。残る不揃いは、実際に区域が変わったもの・人口0のもの・未確認のものだけです。

## 適用範囲

対象は **住基Excel内の年次間の名寄せ**だけです。県が同じ字を年によって違う書き方で
載せているものを、どうつなぐか（あるいはつながないか）を決めます。

住基データと**国勢調査小地域の対応付けは対象外**です。あちらは調査区ベースで
切り方そのものが違うため、別の突き合わせが要ります（Phase 4以降）。
`data/aza_crosswalk.csv` の現行ヘッダ `municipality,aza_jyuki,aza_census,note` は
国勢調査向けの想定で作られたもので、今回の用途には合いません。論点で扱います。

## 欠落の原因分類

`docs/handoff.md` が挙げた4つの観点（表記ゆれ / 区画の新設・統合 / 県側の記載漏れ /
単に人口ゼロ）に、実データから見つかった8クラスを対応させます。

| クラス | 内容 | 件数 | handoff の観点 |
|---|---|---|---|
| A | 「字X」と「X」の併存 | 400ペア / 29市町村 | 表記ゆれ |
| B | 丁目の漢数字と算用数字 | 71グループ / 3市町村 | 表記ゆれ |
| C | 1〜数年だけ現れる異体字・誤植 | 8系統 | 表記ゆれ |
| D | 語中の「字」の脱落 | 1件 | 表記ゆれ |
| E | 住居表示化・区画整理 | 約30系列 | 区画の新設・統合 |
| F | その年だけ掲載粒度が細かい | 8件 | 記載の揺れ |
| G | 実測値としての人口ゼロ | 76件＋宜野湾市の残余字19件 | 単に人口ゼロ |
| H | 原因不明・要確認 | 数件 | 県側の記載漏れの可能性 |

### A — 「字X」と「X」の併存

400ペア、29市町村。`字安謝` と `安謝` のように、同じ字が年によって「字」付きだったり
無印だったりします。

- **同一年に両方が現れるペアは 0件**。年集合は完全に排他です
- 385ペアは、合算するとちょうど15年になります
- 切替は「この年から」ではありません。**県が往復しています**

最多の2パターン:

```
76件   字あり = 2011, 2012, 2013,       2015, 2016
       無印   =                   2014,             2017〜2025

49件   字あり = 2011, 2012, 2013
       無印   =                   2014〜2025
```

つまり2014年と2019年あたりに、県の側で編集の揺り戻しが起きています。
単純に「2014年以降は無印」というルールでは説明できません。

### B — 丁目の漢数字と算用数字

71グループ（名護市43・うるま市26・嘉手納町2）。同一年の衝突は 0件。

```
大中1丁目   2011〜2013     大中一丁目   2014〜2025
城1丁目     2011〜2013     城一丁目     2014〜2025
```

**NFKC正規化では吸収できません。** 全角数字は1件も無く（`１丁目` は存在しない）、
揺れているのは漢数字 `一` と算用数字 `1` の間だからです。`fetch_aza_population.py` の
`norm_name()` は NFKC を通していますが、ここは素通りします。

Aと合わせて正規化すると、系列は **1,780 → 1,309**、15年完全は **673 → 1,121**、
9年未満は **611 → 80** になります。

## 論点1 — 分類A・Bを機械ルールで吸収するか、crosswalk に全件書くか

対象は 471グループ（A 400 + B 71）。これを決めると 611件の thin のうち 531件が片付きます。

### A案：`fetch_aza_population.py` に正規化ルールを持つ

先頭の「字」を落とし、末尾の `一丁目` を `1丁目` に変換したキーで系列をまとめる。

- 新年度に県がまた表記を変えても、追記なしで追随する
- 471グループの人手確認が不要
- **副作用**：ルールが暗黙になる。将来「字X」と「X」が別の実体として同時に立った場合、
  静かに合算する。「同一年の衝突0件」は現時点の観測にすぎず、保証ではない

### B案：`data/aza_crosswalk.csv` に471行すべて書く

- どの字をどの字に寄せたかが1行ずつ残る。あとから第三者が検証できる
- **副作用**：初期に471行を承認する手間。県が表記を戻すたびに追記が必要で、
  追記漏れがあると系列が割れたまま気づけない

### 推奨：A案 ＋ 衝突検知

正規化ルールを入れたうえで、**同一年に同じキーの表記が2つ以上来たらその年の変換を
失敗させる**。市町村名で採った `UnknownMunicipality`（41市町村の正式名に無ければ落とす）
と同じ考え方です。推測で寄せず、想定外は落として人に見せる。

これなら A案の運用の軽さを取りつつ、A案の副作用（静かな合算）だけを潰せます。

**選択：A案 ＋ 衝突検知**（2026-07-31 決定）

Phase 3 での実装内容:

1. `fetch_aza_population.py` に正規化ルールを入れる
   - 先頭が `字` なら1文字落とす
   - 末尾が `[一二三四五六七八九十]+丁目` なら算用数字の `N丁目` に変換する
2. 同一年・同一キーに複数の表記が現れたら、`UnknownMunicipality` と同様に
   **その年の変換を失敗させる**。合算はしない
3. `aza_quality_report.json` に、どの表記をどのキーへ寄せたかの一覧
   （`normalized_groups`）を毎回出す。証拠が残らないという A案の弱点を補う

## 論点2 — 分類Cの異体字（8系統）をどう扱うか

### A案：コード内の辞書（`AZA_TYPOS`）で補正する

市町村名の `MUNI_TYPOS` と同じ形。

- 判断の余地がない誤植には向いている（`玉字城` は明らかに `玉城` の誤植）
- **副作用**：判断の根拠がコードのコメントにしか残らない。
  「県が表記を変えた」ケースまで誤植として片付けてしまう

### B案：`data/aza_crosswalk.csv` に載せる

- 1件ずつ根拠と決定日を書ける
- **副作用**：`MUNI_TYPOS` と管理場所が分かれる

## 論点4 — 基準日の混在をどう表示するか

平成23〜25年（2011〜2013）は **3月31日現在**、平成26年（2014）以降は **1月1日現在**。
同じ「2013年」と「2014年」の間は、実際には **10か月**しか空いていません。

`population_aza.json` の `date` には既に正しい日付が入っています（`2013-03-31`,
`2014-01-01`）。決めるのは表示側だけです。

### 測定結果：「へこみ」は検出できませんでした（2026-07-31）

10か月ぶんしか進んでいないなら、この区間の伸びは他より小さいはずです。実測:

```
県計（字の合計）        系列ごとの前年比・中央値（100人以上の系列）
2012  +0.66%           2011->2012  +0.000%
2013  +0.41%           2012->2013  -0.195%
2014  +0.68%  ←10か月   2013->2014  +0.123%  ←10か月
2015  +0.20%           2014->2015  -0.251%
2016  +0.42%           2015->2016  -0.198%
```

**2013→2014 はむしろ他の年より大きく出ています。** 10か月ぶんという事実は動きませんが、
その効果（本来の 10/12 = 83%）は年ごとの変動のばらつきに埋もれています。
沖縄の字の年変化は多くが ±0.5% 以内なので、そこから17%削っても 0.08ポイントです。

**この測定には弱点があります。** 2013→2014 のサンプルは744系列で、他の年（約1,070）より
3割少ない。まさにこの年に「字X」→「X」の切替が集中し、前年比を計算できるペアが
減っているためです。**論点1の正規化を実装したあとに測り直してください。**

### A案：同一線で結び、注記を添える

- 実装が最も簡単。測定上もへこみは見えない
- **副作用**：10か月であるという事実が画面から消える。注記を読まない人には伝わらない

### B案：2013年と2014年の間で線を切り、点は両方打つ

- 基準が変わったことが線の形で分かる
- **副作用**：1,309系列すべてに同じ位置で切れ目が入る。毎回同じ情報なので、
  2枚目以降は情報量ゼロのノイズになる

### C案：2014年以降を既定表示にし、2011〜2013年は「参考」トグルで出す

- 既定の推移が完全に均質になる
- **副作用**：15年分あるのに12年分しか見えない。データを持っているのに隠すことになる

### D案：横軸を「年」ではなく「実際の日付」で描く

現在の `trendSVG()` は横軸に年番号を使っています（`app/template.html:327`）。

```js
const px=y=>L+(W-L-R)*((y-x0)/((x1-x0)||1));   // 年番号で等間隔
```

これを `date` の実日付に変えると、2013-03-31 と 2014-01-01 の間隔は
**自動的に他の 3/4 の幅**になります。変更は横軸の計算1箇所です。

- 線の傾き（＝変化の速さ）が**正しくなる**。注記に頼らず、グラフの形が事実と一致する
- 切れ目を入れないので見た目が壊れない
- **副作用**：横軸の目盛りが2011〜2014だけわずかに不等間隔になる

### 推奨：D案 ＋ 基準日の明示

B案は1,309系列すべてに同じ切れ目が入ります。1枚目は伝わりますが、2枚目からは
「またこれか」になり、注意を引く力を失います。**警告は毎回同じ場所に出ると効かなくなります。**

D案は、警告ではなく**描画そのものを正しくする**やり方です。10か月ぶんの変化を
10か月ぶんの幅で描けば、傾きは自動的に正しくなります。C案は情報を捨てるので採りません。

**選択：D案（横軸を実日付に）**（2026-07-31 決定）

Phase 3 での実装内容:

1. `trendSVG()` の `px()` を、`r.year` ではなく `r.date` から作った実数年
   （例 `2013-03-31` → `2013.246`）で計算する
2. 目盛りラベルは従来どおり年（2011, 2013, …）を出す
3. 各点の値を出すとき（表・ツールチップ・aria-label）に**基準日を併記**する。
   「2013年（平成25年3月31日現在）4,024人」の形
4. 市町村レイヤーの国勢調査系グラフは基準日が別なので、この変更を波及させない

## 論点5 — 人口ゼロの見せ方（分類G）

### この層に「回答なし」は存在しません（2026-07-31 実測）

`population` が `null` のレコードは **18,390件中0件**。値があれば、それは県が実際に
載せた数字です。したがって CLAUDE.md 原則3 は、字レイヤーでは別の形で現れます。

| 状態 | データ上の形 | 意味 |
|---|---|---|
| 値あり | `population: 3,445` | 県が3,445人と載せた |
| **実測の0** | `population: 0` | **県が「0人」と載せた**。住民登録がない |
| **掲載なし** | **その年の行が存在しない** | 県がその年に載せていない |

区別すべきは「0」と「回答なし」ではなく、**「0」と「掲載なし」**です。
掲載なしは値が空なのではなく、**行が丸ごと無い**形で現れます。

### 実測：0は5.8%

正規化後1,309系列のうち、

| | 件数 |
|---|---|
| 全年0 | **76**（うち9年未満が27） |
| 最終年が0（消えかけの区域） | 101 |
| 一部の年だけ0 | 31 |

全年0の内訳: 沖縄市17・那覇市14・浦添市12・宜野湾市11・うるま市8・嘉手納町4・
石垣市4・読谷村3・名護市2・北大東村1。

### 0には意味の違う2種類があります

**(1) その区域に人が住んでいない** — 15年通して県が毎年「0人」と載せているものが12件。

```
石垣市 登野城尖閣            尖閣諸島
石垣市 南ぬ島町 / 南ぬ浜町     空港・埋立地
那覇市 大嶺 / 具志 / 高良      那覇空港の区域
那覇市 通堂町 / 住吉町1〜3丁目  港湾地区
沖縄市 KADENAAIRBASE       米軍施設
北大東村 ラサ               ラサ工業の跡地
```

**これは正しい情報**で、隠すべきではありません。尖閣諸島の人口が0であることは
データとして意味があります。

**(2) 住居表示化で丁目に移りきった残余区域** — 宜野湾市が典型。19の字が、
同名の丁目と**同じ年に並んで載っています**。

```
大山    2025 = 0     併存: 大山1丁目 … 大山7丁目
野嵩    2025 = 0     併存: 野嵩1丁目 … 野嵩4丁目
我如古   2025 = 622   併存: 我如古1丁目 … 我如古4丁目   ← 人が残っている
真栄原   2025 = 61    併存: 真栄原1丁目 … 真栄原3丁目
赤道    2025 = 31    併存: 赤道1丁目 赤道2丁目
```

19件中16件が0、3件に人が残っています。**統合してはいけません**
（統合すると `大山` の人口が丁目ぶん二重に足されます）。論点1の正規化では
巻き込まれません（無印の `大山` と `大山1丁目` は別キー）が、`relation=separate` で
明示しておかないと将来誰かが寄せます。

**選択：(a) 検索では出し一覧では畳む ／ (b) 掲載なしの区間は線を切る ／
(c) 残余区域と明示して丁目へリンク**（2026-07-31 決定）

Phase 3 での実装内容:

1. **全年0の76件** — 検索では通常どおりヒットさせる。一覧では
   「住民登録のない区域 76件」として折りたたみ、開けば見える形にする
2. **掲載なしの年** — その区間は線を引かない。点も打たない。
   補間も破線も使わない。「データがない」と「0人だった」が線の形で完全に区別される
3. **実測の0** — 0の位置に点を打ち、線でつなぐ。凡例で「0人（県が0と公表）」と明示する
4. **残余字** — 「この区域の大部分は大山1〜7丁目へ移行済み」と出し、丁目へリンクする。
   crosswalk に `relation=separate` で統合禁止を明記（宜野湾市19件ほか）
5. **合算値は作らない** — 「大山地区合計（字＋1〜7丁目）」のような参考値は出さない。
   出典のない数値を作ることになるため（原則1）

### Phase 3 の検証項目
