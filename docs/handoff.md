# 実装の進め方 — フェーズと指示テンプレート

各フェーズの冒頭に書いてある `/model` を実行してから、その下の指示をそのまま貼る。
フェーズが終わったら `/clear` で区切る。`CLAUDE.md` の内容は `/clear` でも `/compact` でも保持されるので、
毎回プロジェクト説明を貼り直す必要はない。

## 使うコマンド

| コマンド | 用途 |
|---|---|
| `/init` | 初回にCLAUDE.mdの雛形を生成（本リポジトリは同梱済みなので不要） |
| `/model` | モデルを切り替える |
| `/effort` | 推論の深さを変える |
| `/plan` | 大きな変更の前に、実装せず計画だけ立てさせる |
| `/context` | いま何がコンテキストを埋めているか見る |
| `/compact` | 会話を要約して圧縮する |
| `/clear` | 履歴を消して次のタスクへ。フェーズの区切りで使う |

`Shift+Tab` でプランモード / 編集承認 / 自動モードを切り替えられる。

## Phase 0 — 準備

GitHubが初めてなら [setup-github.md](setup-github.md) の手順どおりに進めてください。
ターミナルもPythonも使わず、クリック操作だけで公開までいきます。

コマンドラインに慣れている場合はこれだけです。

```bash
cd okinawa-atlas
git init && git add -A && git commit -m "初期構成: 調査ETL + プロトタイプUI"
gh repo create okinawa-atlas --public --source=. --push
```

いずれの場合も、GitHub の Settings → Pages → Source を **GitHub Actions** にするのを忘れないこと。

## Phase 1 — 字別人口を通す（Sonnet）

はじめる前に、Python と Claude Code の準備を [setup-windows.md](setup-windows.md) で済ませてください。

15年分のExcelはヘッダ位置も列名も揺れている。落ちた年を直す反復作業なので、判定基準が明確。

```
/model sonnet
```

```
scripts/fetch_aza_population.py を実行して、平成23年〜令和7年の15ファイルすべてから
字別人口を取り出せる状態にしてください。

進め方:
1. まず全年ダウンロードして、どの年が変換に失敗するかを一覧にする
2. 失敗した年のExcelを1つずつ確認して read_year() を対応させる
3. 各年について「取れた字数」を出し、年ごとに極端な差がないか確認する

制約:
- 字名や人口を推測で補完しない。取れないものは失敗として報告する
- 平成23〜25年は3月31日現在、平成26年以降は1月1日現在。date フィールドを正しく入れる
- 全年通ったら、実行末尾に出る「年次が欠けている字」の一覧をそのまま見せてください。
  ここは私が判断するので、crosswalk はまだ書かないこと
```

## Phase 2 — 名寄せ方針を決める（Opus・プランモード）

ここが間違うと全指標が静かにずれる。エラーも出ない。人が決める。

```

/plan
```

```
Phase 1 で出た「年次が欠けている字」の一覧を分析して、名寄せの方針を提案してください。
実装はまだしないこと。

見てほしい観点:
- 欠落の原因を分類する（字名の表記ゆれ / 区画の新設・統合 / 県側の記載漏れ / 単に人口ゼロ）
- 分類ごとに、推移グラフでどう扱うのが正しいか。特に統合・分割された字を
  「1本の系列としてつなぐ」のか「別系列として不連続を見せる」のか
- 平成23〜25年（3月31日現在）と平成26年以降（1月1日現在）が混在した推移を
  どう表示するか。同一線で結んでよいのか、注記で足りるのか
- data/aza_crosswalk.csv のスキーマ。あとから人が追記しやすい形にしたい

出力: 方針を docs/aza-matching-policy.md に書き、判断が分かれる箇所は
「A案/B案 + それぞれの副作用」の形で並べてください。私が選びます。
```

方針が決まったら、その決定を `CLAUDE.md` の「データソースと落とし穴」に1〜2行で反映させておく。
以降のセッションが同じ判断を引き継げる。

## Phase 4 — 市町村の人口データ投入（Sonnet）実施済み（2026-08-01）

```
/model sonnet
/clear
```

```
市町村レイヤーの人口データを実データに差し替えてください。

必要なもの:
- 市町村別人口推移: 国勢調査 1980–2020 + 令和7年 人口速報集計（2026-05-29公表）
- 市町村別ピラミッド: 令和2年国勢調査 人口等基本集計（5歳階級×男女）

進め方:
1. まず小さく1件だけ、e-Stat APIから実際にデータが取得できるかテストする
2. scripts/fetch_census.py を新規に作る。e-Stat の appId は環境変数 ESTAT_APP_ID から読み、
   コードにもコミット履歴にも残さないこと
3. data/generated/population_muni.json を出す
4. app/template.html の demoMuni を削除して差し替え、対応する .dummy を外す
5. 令和7年速報は男女別人口と世帯総数のみで年齢別がない。推移グラフには載せるが、
   ピラミッドには使わず、出典年を画面に明記すること
```

**実施結果**: 統計表IDは市町村別人口推移が国勢調査の回ごとに別表（1980〜2020年で9種類、
`scripts/fetch_census.py` の `CENSUS_TABLES` に記載）、市町村別ピラミッドは
`0003445162`（令和2年国勢調査 人口等基本集計）、令和7年速報は `0004050397`（男女別人口）
＋ `0004050417`（世帯数）。宮古島市・うるま市・久米島町（1980〜2000年）、南城市・八重瀬町
（1980〜2005年）は合併前の旧市町村コードの実測値を単純合算し、その区間は推移グラフを
破線・淡色で区別している（豊見城市は村→市のコード変更のみで合併ではないため区別しない）。
2020年の県計は1,467,480人で県公表値と一致を確認済み。

字別年齢構成（令和2年国勢調査 小地域集計）はe-Stat APIの `getStatsList` で
統計表IDが見つからず、今回のスコープから外した。Phase 5 を参照。

## Phase 5 — 字別年齢構成（小地域集計）投入（Sonnet）実施済み（2026-08-01）

**実施結果**: 令和2年国勢調査 小地域集計はAPIではなく、政府統計の総合窓口の
CSVファイル配布（統計表ID `000032163785`、Shift-JIS）だった。`scripts/fetch_aza_census.py`
が沖縄県全域1ファイル（4,493行）をダウンロードし、階層構造（丁目のある字は小計行と
丁目行の二重計上に注意）・秘匿処理（`X`＝近隣字に合算され復元不能。実測0の`-`とは別）・
「字」接頭辞の有無（住基側は落ちていることが多い）を踏まえて突合する。
`data/aza_census_crosswalk.csv` を機械的に生成し、1,296字中1,155字が対応、7字は
秘匿処理、120字は未対応（大半は2020年国勢調査より後にできた新しい丁目）。
残り14字（シールズ基地、キャンプフォスターなど）は米軍基地関連と見られ、国勢調査側に
該当する行が一件も無いことを確認したが、総務省統計局の公式な「対象外」説明までは
確認できていないため、`POSSIBLY_OUT_OF_SCOPE` に列挙し「対象外の可能性（推定）」と
断定しない形で扱う（確証が取れたら `CONFIRMED_OUT_OF_SCOPE` に移す）。
`app/template.html` の字レイヤー年齢構成から `.dummy` を外し、秘匿処理・未対応・
対象外の可能性は理由を明示したうえでサンプル値のまま残している。

## Phase 6 — マップ（Sonnet）着手済み（2026-08-01）。動作確認が未完了

**実施結果**: 環境確認とサイズ実測は使い捨てワークフローで実施し、削除済み。
tippecanoeはWindowsに公式バイナリが無いため、ローカルではなくGitHub Actions
（Ubuntuランナー）上でソースからビルドする方針にした。市町村ポリゴンは
別ソースを使わず、字ポリゴン（r2ka47）をCITYコードでdissolveして作る
（基準時点を字と完全に揃えるため）。実測サイズは字4.13MB／市町村0.12MB
（GitHub上限100MB/1GBに対して十分小さい）。

- `scripts/build_tiles.sh` — ogr2ogr(dissolve) → tippecanoe×2（字/市町村） →
  tile-join で `public/tiles/okinawa.pmtiles` を作る
- `.github/workflows/build-tiles.yml` — `workflow_dispatch`専用。`pages.yml`には
  含めない。生成物は**自動コミットせずartifactとして出す**。人がダウンロードして
  ブラウザで目視確認してからコミットする運用（バイナリでPRの差分レビューが
  しにくいため）
- `app/template.html` — `.mapslot`をMapLibre GL JS 4.7.1 + pmtiles 4.4.1（CDN）の
  実マップに置き換え済み。ズームで市町村/字レイヤーを切り替え、クリックで
  `go()`に接続（市町村はCITYコードで確実に一致、字は境界ポリゴンのS_NAMEと
  住基側の字名をその場で正規化して突合。一致しないものはクリックしても
  遷移しない）

**未完了**:
- `public/tiles/okinawa.pmtiles` がまだリポジトリに無いため、地図の動作確認が
  できていない。`build-tiles.yml`を手動実行→artifactをダウンロード→
  `python -m http.server -d public 8000`で目視確認→問題なければ
  `public/tiles/okinawa.pmtiles`をコミット、という手順が必要
- 指標セレクタに連動したコロプレス塗り分け（「回答なし」のハッチング表現）は
  未実装。地図の表示自体が確認できてから着手する想定

## Phase 8 — 公開と運用

公開の前に [publish-checklist.md](publish-checklist.md) を自分の目で通してください。
ここはClaudeに委任しないこと。ETLが壊れていても画面は正常に見えます。

```bash
git add -A && git commit -m "実データ接続とマップを追加" && git push
```

Actions が走って Pages に出る。以降の年次更新は、

1. 新しい調査Excelを `data/raw/survey/latest.xlsx` に置き換えてpush
2. 県が新年度の町字別人口を公開したら `fetch_aza_population.py` の `FILES` に1行追加してpush

Actions が両方を再変換してビルドし、`quality_report.json` の要約を実行サマリに出す。

## モデル切り替えの目安

| 場面 | モデル |
|---|---|
| 合否がその場で分かる（パーサを通す、配線する、CSSを詰める） | Sonnet |
| エラーが出ないまま間違いうる（名寄せ、指標定義、公開前レビュー） | Opus |
| 判断に迷ったとき | Opus で `/plan` を使い、実装はSonnetに渡す |

やり直しのコストが実行のコストより高い作業だけOpusに回す、という基準で足りる。

## claude.ai 側での切り替え

設計の相談や仕様の議論をチャットで行う場合は、入力欄のモデル選択から切り替える。
同じスレッド内で切り替えれば、それまでの経緯は文脈として引き継がれるので、
新しい会話を立てるより引き継ぎが楽になる。
