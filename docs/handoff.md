# 実装の進め方 — フェーズと指示テンプレート

各フェーズの冒頭に書いてある `/model` を実行してから、その下の指示をそのまま貼る。
フェーズが終わったら `/clear` で区切る。`CLAUDE.md` の内容は `/clear` でも `/compact` でも保持されるので、
毎回プロジェクト説明を貼り直す必要はない。

## 使うコマンド

| コマンド | 用途 |
|---|---|
| `/init` | 初回にCLAUDE.mdの雛形を生成（本リポジトリは同梱済みなので不要） |
| `/model` | モデルを切り替える |
| `/effort` | 推論の深さを変える |
| `/plan` | 大きな変更の前に、実装せず計画だけ立てさせる |
| `/context` | いま何がコンテキストを埋めているか見る |
| `/compact` | 会話を要約して圧縮する |
| `/clear` | 履歴を消して次のタスクへ。フェーズの区切りで使う |

`Shift+Tab` でプランモード / 編集承認 / 自動モードを切り替えられる。

```

## Phase 4 — 市町村の人口データ投入（Sonnet）実施済み（2026-08-01）

```
/model sonnet
/clear
```

```

進め方:
1. まず小さく1件だけ、e-Stat APIから実際にデータが取得できるかテストする
2. scripts/fetch_census.py を新規に作る。e-Stat の appId は環境変数 ESTAT_APP_ID から読み、

4. app/template.html の demoMuni を削除して差し替え、対応する .dummy を外す
5. 令和7年速報は男女別人口と世帯総数のみで年齢別がない。推移グラフには載せるが、

`scripts/fetch_census.py` の `CENSUS_TABLES` に記載）、市町村別ピラミッドは
`0003445162`（令和2年国勢調査 人口等基本集計）、令和7年速報は `0004050397`（男女別人口）
＋ `0004050417`（世帯数）。宮古島市・うるま市・久米島町（1980〜2000年）、南城市・八重瀬町

破線・淡色で区別している（豊見城市は村→市のコード変更のみで合併ではないため区別しない）。
2020年の県計は1,467,480人で県公表値と一致を確認済み。

字別年齢構成（令和2年国勢調査 小地域集計）はe-Stat APIの `getStatsList` で
統計表IDが見つからず、今回のスコープから外した。Phase 5 を参照。

## Phase 5 — 字別年齢構成（小地域集計）投入（Sonnet）実施済み（2026-08-01）

**実施結果**: 令和2年国勢調査 小地域集計はAPIではなく、政府統計の総合窓口の
CSVファイル配布（統計表ID `000032163785`、Shift-JIS）だった。`scripts/fetch_aza_census.py`
が沖縄県全域1ファイル（4,493行）をダウンロードし、階層構造（丁目のある字は小計行と
丁目行の二重計上に注意）・秘匿処理（`X`＝近隣字に合算され復元不能。実測0の`-`とは別）・
「字」接頭辞の有無（住基側は落ちていることが多い）を踏まえて突合する。
`data/aza_census_crosswalk.csv` を機械的に生成し、1,296字中1,155字が対応、7字は
秘匿処理、120字は未対応（大半は2020年国勢調査より後にできた新しい丁目）。
残り14字（シールズ基地、キャンプフォスターなど）は米軍基地関連と見られ、国勢調査側に
該当する行が一件も無いことを確認したが、総務省統計局の公式な「対象外」説明までは
確認できていないため、`POSSIBLY_OUT_OF_SCOPE` に列挙し「対象外の可能性（推定）」と
断定しない形で扱う（確証が取れたら `CONFIRMED_OUT_OF_SCOPE` に移す）。
`app/template.html` の字レイヤー年齢構成から `.dummy` を外し、秘匿処理・未対応・
対象外の可能性は理由を明示したうえでサンプル値のまま残している。

## Phase 6 — マップ（Sonnet）実施済み（2026-08-01）。動作確認完了（2026-08-03）

**実施結果**: 環境確認とサイズ実測は使い捨てワークフローで実施し、削除済み。
tippecanoeはWindowsに公式バイナリが無いため、ローカルではなくGitHub Actions
（Ubuntuランナー）上でソースからビルドする方針にした。市町村ポリゴンは
別ソースを使わず、字ポリゴン（r2ka47）をCITYコードでdissolveして作る
（基準時点を字と完全に揃えるため）。実測サイズは字4.13MB／市町村0.12MB
（GitHub上限100MB/1GBに対して十分小さい）。

- `scripts/build_tiles.sh` — ogr2ogr(dissolve) → tippecanoe×2（字/市町村） →
  tile-join で `public/tiles/okinawa.pmtiles` を作る
- `.github/workflows/build-tiles.yml` — `workflow_dispatch`専用。`pages.yml`には
  含めない。生成物は**自動コミットせずartifactとして出す**。人がダウンロードして
  ブラウザで目視確認してからコミットする運用（バイナリでPRの差分レビューが
  しにくいため）

  `go()`に接続（市町村はCITYコードで確実に一致、字は境界ポリゴンのS_NAMEと
  住基側の字名をその場で正規化して突合。一致しないものはクリックしても
  遷移しない）

**動作確認**: `build-tiles.yml`の手動実行→artifactダウンロード→目視確認を経て、
`public/tiles/okinawa.pmtiles` はコミット済み（`91a2dba`）。境界そのものは pmtiles.io で

ブラウザで確認済み（2026-08-03）**。なお自動操作タブは `visibilityState:"hidden"` で
`requestAnimationFrame` が発火せずMapLibreの初期化が完了しないため、ここは
ブラウザ自動操作では検証できない。人が開いて見るしかない。

## Phase 9 — 公開前レビュー後のデザイン改善（Opus・プランモード）実施済み（2026-08-03）

Phase 7 のレビューを受けて、実データが載った状態で見えてきた表示上の問題を4点直した。
モックを提示して合意してから実装する手順で進めた（プランは `/plan` で作成・承認）。

**実施結果**:

1. **花ブロック（`hanaSVG`）を廃止し、横棒グラフ一覧に置き換えた。** 値ラベルを図の上に絶対配置
   していて数字が読めなかったのが理由。県ページの指標一覧と市町村ページの字一覧の**両方**が対象。
   3状態の符号は `barTrack()` に移植した（**点線のトラック＝回答なし／原点の実線マーク＝実測0／
   バー＝正の値**）。値ラベルも `barValue()` で「回答なし」「0（実測）」と書き分ける。
   並び順セレクタを追加し、**`null` の行は値順のとき必ず最下部にまとめる**（昇順で空欄が
   先頭を埋めると読めないため）。既定は県ページが市町村コード順（推定空家数は基準年が混在する
   ため、既定を値順にすると年度をまたいだ順位表として読まれる）、字一覧が人口の多い順。
   推定空家数の行には基準年バッジを併記した（実データで「基準あり」4件・「基準年不明」6件）。
2. **人口ピラミッドの向きを統一した。** 調査したところ市町村・字・サンプル値の**全経路が逆**
   （年少層が上）だった。データ側は3経路とも `0-4` → `85+` の昇順なので、`pyramidSVG()` が
   描画時に反転する形にした。この1関数で3経路とも直る。
3. **市町村ページに、その市町村の字だけを塗った地図を追加した。** クリックで字レイヤーへ
   （突合は既存の `matchAzaName()` を再利用）、**ホバーで「市町村名／字名」の吹き出し**
   （`.maptip`。県全体の地図には出さない）。市町村ごとの外接矩形を持っていないため、
   県全域で読み込んでから `querySourceFeatures` の bbox で寄せる。
   **`minZoom` を先に7にすると初期表示が丸められ、遠い離島のタイルが読まれず寄せに失敗する**
   （初期ズームの実測は5.94）。`minZoom:4` で読ませ、寄せ終わってから `setMinZoom(7)` する。
4. **戻るUIを強化した。** ヘッダーに「← 沖縄県全体に戻る」を常設（県ページでも消さず無効表示。
   消すとヘッダー幅が変わってパンくずの位置がずれる）、パンくずをチップ型ボタンに。

**`CLAUDE.md` の方針を書き換えた。** 1 は「花ブロックは棒グラフ一覧に置き換えない」という
それまでの方針と正面から矛盾するため、原則3・UIの方針・構成の3箇所を横棒グラフ前提に更新した。
原則3の実質（`0` と「回答なし」を混同しない、`v!=null` で数える）は維持している。

**`scripts/serve.py` を追加した。** 確認用に使っていた `python -m http.server` は
Rangeリクエストに対応せず `206` を返さないため、**pmtiles を読めず地図だけが表示されない**
（他は正常に見えるので気づきにくい）。GitHub Pages は Range 対応なので本番では起きない。

**確認**: 指標4種×並び順3種と市町村・字ページをヘッドレスChromeでレンダリングし、
3状態の内訳がデータと一致すること（推定空家数 10/0/31、バンク 6/2/33、定住促進住宅 20/21/0、
総人口 41/0/0）とピラミッドの向きをSVGのy座標で確認。**地図はヘッドレスでは検証できないため、
うるま市・竹富町・那覇市・渡名喜村を人がブラウザで目視確認済み**（問題なし）。

**未完了**（Phase 6 から継続）: 指標セレクタに連動したコロプレス塗り分けは未実装。
URLでの画面指定（ハッシュルーティング）も未実装で、市町村ページを直接指すURLは作れない。

## モデル切り替えの目安

| 場面 | モデル |
|---|---|
| 合否がその場で分かる（パーサを通す、配線する、CSSを詰める） | Sonnet |
| エラーが出ないまま間違いうる（名寄せ、指標定義、公開前レビュー） | Opus |
| 判断に迷ったとき | Opus で `/plan` を使い、実装はSonnetに渡す |

やり直しのコストが実行のコストより高い作業だけOpusに回す、という基準で足りる。

## claude.ai 側での切り替え

設計の相談や仕様の議論をチャットで行う場合は、入力欄のモデル選択から切り替える。
同じスレッド内で切り替えれば、それまでの経緯は文脈として引き継がれるので、
新しい会話を立てるより引き継ぎが楽になる。
